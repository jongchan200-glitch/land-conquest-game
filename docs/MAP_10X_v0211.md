# 땅따먹기 v0.2.11 — 캐릭터 카드 배경 + 10배 맵 + 귀여운 홈 3D 조정

2026-11-23 | 기존 v0.2.10 기준, canonical GitHub `main/index.html` 증분 패치.

## 사용자 승인 및 원본 보존
- 승인된 홈 캐릭터 시안(귀여운 작고 둥근 복숭아빛 애벌레, 가는 단일 원형 수염, 짧고 뾰족하지 않은 꼬리)을 참고해 로비 3D의 **크기를 줄이고**, 눈·얼굴·입 둘레·꼬리의 부피 및 초기 회전 각도를 조정했다. 승인된 2D 정본 아틀라스 원본 파일은 변경하지 않았다.
- 기존 두 캐릭터 카드 사진(CHAR_001 유해나, CHAR_002 아니카) 데이터 URI를 **모두 바이트 단위 그대로 보존**했다. 데이터 소스 전체 SHA256: `aee4d1064dfb148c59627fe5128bc30d33d8bbe3f7d5064310cd0d5175e6df5e`. 스테이지 1은 원래 CHAR_001 사진을 사진 배경으로 사용하고, 스테이지 2는 원래 CHAR_002 이미지로 넘어가는 매핑을 그대로 유지한다. 이미지 생성/편집/미러링/덮어쓰기 없음.
- 사진이 보이는 조건은 이전과 동일: 크래커가 자기 소유 땅으로 바뀌어 사라진 부분만 아래 사진이 드러난다.

## 맵 크기
- 이전 34 × 48 = 1,632셀 → 새 108 × 152 = **16,416셀, 정확히 10.0588235배 면적**. 가로와 세로를 각각 10배로 해 100배가 되는 실수 방지.
- 월드 1셀은 25px 그대로, 기존 플레이어/몬스터 크기·포만 8번·최대 몸 길이 15칸(레벨 보정)·점령 68% 목표는 유지.
- 시작 OWN 띠는 전체 폭에 비례해 5/34 비율(16셀), 플레이어는 같은 상대적 좌표로 배치. 새 판의 초기 점령률은 약 14.81%.
- 10배 공간에서 적들이 한 장소에 몰리지 않게 기존 네 종류 몬스터 3묶음(총 12마리)을 월드 전역에 배치. 몬스터 자체 크기는 v0.2.10의 2.5배 설정을 그대로 유지. 기존 저장 게임의 몬스터 위치는 영역 비율에 맞게 이전됨.

## 저장 호환
- 기존 저장키 `land-conquest-v02-solo-local` 유지. 34×48 저장 월드를 108×152로 확대하는 동안 타일 점령 모양·레벨·XP·코인·앨범·강화·스테이지·목숨을 마이그레이션.
- 10배 확장 전에 기존 저장 객체를 `land-conquest-v02-solo-local-backup-before-v0211`로 별도 백업(한 번만)한 뒤 새 배열로 기록.
- 앞으로 20배·30배 확장을 위해 `mapCols`, `mapRows`를 저장하고 새로운 임의 크기 → 다음 크기 resampling 경로 포함.
- 기존 사진 경로/파일을 바꾸지 않음.

## 모바일 렌더링 성능
- 2700×3800px **전체 판 크기 캐시를 매번 생성하지 않음**. camera 뷰포트의 가시 타일 부분만 slab(크래커) 캐시를 만들어 움직임·한입 후 무효화 시 재생성. 일정한 전역 타일 해시로 결을 유지.
- 사진 렌더도 크래커 배경과 같은 화면 가시 사각형의 원본 사진 부분만 확대하여 그린다. 이는 원본 이미지의 외형을 변형하거나 새 사진으로 교체하지 않는 디스플레이 최적화이다.
- 가시 범위 밖 추락한 크래커 파편은 생략해 그리기 비용 감소. 판정·획득·저장은 월드 전체 기준.

## 실행/검수
- Python Playwright + Chromium 모바일 390×844에서 직접 실행. 108×152 = 16,416 셀 검사, 실제 유해나 사진을 부분 점령하여 아래에서 드러냄, 기존 사진과 새 사진의 데이터 URI SHA256 원문 비교 일치.
- 초기/구 버전 저장 데이터 마이그레이션: 구버전 레벨3·코인137·앨범 수집 및 기존 점령률 약26.5%는 신버전 약26.85%로 유지(리샘플 격자 반올림). 사진 source 매핑 그대로.
- 몬스터 12개 배치, 조이스틱+액션 진입, 11칸 둘러싸기 점령 정상: 14.81% → 14.91%; 목숨 유지; 상점 40코인 구매(65→25, 포만 용량 +1 업그레이드) 정상.
- 캐릭터 홈 3D 정면/측면/후면/반대 측면 회전 연속 프레임 확인. 런타임 JS 오류 0.
- 실제 삼성 Galaxy에서 프레임/멀티터치/디자인 최종 검수는 사용자 확인 전. 3D 홈 모델은 승인 이미지와 같은 느낌에 가깝게 개선한 단계이며 이미지 픽셀 단위 동일 모델이라고 주장하지 않음.
